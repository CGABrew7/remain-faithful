# Remain Faithful 1.0.4 App Review notes

Draft for the owner. Do not submit this text until you have checked it against the binary you upload.

Bundle ID: com.remainfaithful.app
Apple ID: 6774615426
This is the same app already on the store as version 1.0. Marketing version 1.0.4.

Family Controls, Managed Settings, and Device Activity shield apps the user selected. Authorization uses FamilyControlsMember.individual. The first screen of the description names that integration.

The Shield Configuration extension (com.remainfaithful.app.ShieldConfig) returns a ShieldConfiguration. It makes no network calls. It does not write an app name, bundle id, or domain.

The Shield Action extension (com.remainfaithful.app.ShieldAction) handles the primary button. On iOS 26.5 and later, the response is ShieldActionResponse.openParentalControlsApp. On earlier versions the extension closes the shield and posts a local notification that opens Remain Faithful. The app then shows "A blocked app was opened" with Tell my partner and Not now. The network call happens only after Tell my partner, from the main app.

The Device Activity monitor extension (com.remainfaithful.app.DeviceActivityMonitor) applies and removes shields on the phone. It makes no network calls.

Server calls from the main app:

- POST /events after Tell my partner. Fields: category app_usage, severity concerning, summary "Blocked app opened", timestamp.
- POST /events while a user-started Deep Scan broadcast is running, from the broadcast upload extension RemainFaithfulBroadcast. Fields: category, severity, summary (a fixed category label), timestamp, tier, confidence_bucket (low, medium, or high).
- POST /protection/alerts for selection_cleared, shielding_disabled, monitoring_disabled, deep_scan_stopped, lockout_disabled, Partner PIN changes, family_controls_revoked, and signed_out. Fields: type, detail.
- POST /check-ins after the user taps Send. Fields: status (steady, need_support, or slipped), note (the user's text, up to 140 characters), shielding_on, session_shield_on, schedule_on, deep_scan_on.
- POST /heartbeat from the main app while protection is on, including foreground and background refresh. Field: screen "monitoring". No usage minutes.

Deep Scan is the ReplayKit broadcast upload extension. The user starts it from the system broadcast picker (RPSystemBroadcastPickerView, preferred extension com.remainfaithful.app.broadcast, or Control Center Screen Recording). iOS shows the recording indicator. Frames are classified on the device with Vision and Sensitive Content Analysis. The upload is the category, severity, tier, confidence bucket, and time.

Session Shield is opt in. Chosen apps stay shielded unless that broadcast is running. The broadcast extension writes an app-group flag and a timestamp and posts a Darwin notification. The main app applies or removes shields when it receives that notification. The Device Activity monitor does the same the next time it runs. If the flag is missing or the timestamp is stale, the apps stay shielded.

One bundle ID. This submission removes the Screen Time extension uploads from 1.0.3.
